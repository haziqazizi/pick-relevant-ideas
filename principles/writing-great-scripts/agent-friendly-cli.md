# agent-friendly-cli

Design commands as automation surfaces, not just human terminal UX.

Use for any script or CLI an agent may run.

## Actions

1. Provide a non-interactive path for every required input.
2. Make help discoverable without reading source.
3. Use stable command shapes, flags, output fields, and exit codes.
4. Print concise success output with IDs, paths, URLs, or next commands.
5. Fail with actionable errors and examples.
6. Support dry-run or explicit confirmation for dangerous effects.

An agent-friendly CLI is also easier for tired humans.
