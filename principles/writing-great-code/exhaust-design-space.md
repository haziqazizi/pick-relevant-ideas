# exhaust-design-space

Do not commit to the first plausible shape when the design space is genuinely
open.

Use for novel UI, architecture, API shape, skill workflow, prompt structure,
browser/iOS integration, and high-stakes refactors.

## Actions

1. Name 2-3 viable alternatives.
2. Compare them against the actual objective.
3. Use separate subagents only when candidates can be explored independently and
   the host supports it.
4. Record why the losing options lost.
5. Carry forward the best rejected detail when useful.

Skip this when local precedent or constraints make one shape obvious.
