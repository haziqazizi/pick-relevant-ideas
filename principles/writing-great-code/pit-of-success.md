# pit-of-success

Make the right thing the easiest thing.

Use for APIs, CLIs, generated templates, install flows, skill instructions,
review gates, and UI workflows.

## Actions

1. Put the common safe path first.
2. Make unsafe paths explicit, named, and harder to trigger.
3. Provide defaults that converge to safe behavior.
4. Replace warnings with constraints when cheap.
5. Test the first-run path, not only the expert path.

If a tired user can easily do the dangerous thing, the design is not finished.
