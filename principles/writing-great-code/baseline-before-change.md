# baseline-before-change

Capture current behavior before changing it.

Use for bug fixes, performance work, visual parity, refactors, migrations, and
QA regressions.

## Actions

1. Run or observe the current behavior.
2. Save the command, screenshot, metric, log, trace, fixture, or failing test.
3. State what would count as improvement or preservation.
4. Change the system.
5. Re-run the same or closer proof.

Without a baseline, "fixed", "faster", and "unchanged" are guesses.
