# user-visible-proof

For user-visible claims, source inspection is not enough.

Use whenever the claim concerns behavior a user directly perceives or controls.

## Actions

1. Drive the real surface or closest faithful repo-declared adapter.
2. Capture the observable state, interaction, or temporal artifact the claim
   requires, plus supporting diagnostics when useful.
3. Re-run the original workflow after a fix.
4. Present the smallest faithful human view and link its authoritative evidence;
   the presentation never upgrades the result.

If the surface cannot be driven, report blocked or not verified.
