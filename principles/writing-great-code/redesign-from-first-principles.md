# redesign-from-first-principles

When a new requirement changes the core shape, redesign as if it had existed
from day one, then deliver incrementally.

Use when adding a requirement that cuts across old assumptions, data shape,
workflow ownership, or interface boundaries.

## Actions

1. State the old assumption.
2. State the new requirement.
3. Sketch the clean design if both had been known upfront.
4. Choose an incremental route toward that design.
5. Avoid bolt-ons that preserve a bad center.

This principle pairs with `outcome-oriented-execution.md`.
