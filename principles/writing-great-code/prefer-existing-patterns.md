# prefer-existing-patterns

Use local precedent before inventing a new shape.

Use when adding APIs, components, scripts, tests, docs, styles, generated
artifacts, or workflow conventions.

## Actions

1. Search for nearby examples.
2. Match naming, error handling, test style, and file layout when good enough.
3. Deviate only for a concrete improvement.
4. Record the reason when introducing a new pattern.

Consistency reduces what the next reader must hold in mind.
